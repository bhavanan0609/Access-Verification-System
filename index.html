Data structures used

This site uses only two structures, both built from scratch with linked nodes. It does not use arrays, stacks, sorting or hashing for its data.

Singly linked list: researcher records. Researchers can be added, revoked, restored and removed at any time, so a linked list grows and shrinks without shifting elements. Looking up an ID walks the list node by node, which takes O(n).

Singly linked list: access history and security activity. Each new decision is inserted at the head in O(1), so the newest entry is always listed first.

Linked queue: pending access requests. Requests are added at the rear (enqueue) and served from the front (dequeue), both in O(1). Requests are handled in the order they arrive.

Verification order

Dequeue request, search researcher list, then check in turn: authentication (ID exists), authorization (zone matches), permission (active), revocation (not revoked) and lockdown (off). Access is denied at the first failed check and granted only if all pass. The decision is stored in the history and activity lists.
